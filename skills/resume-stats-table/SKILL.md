# 校招简历信息统计表生成

把一批应届生简历（PDF）按一份「校招人员信息统计表」**固定模板 Excel**（如 `固定模板.xlsx`，含
杭州岗/杭州面试名单/面试安排/211&985院校名单/录用填写表 等多个 sheet）整理成新一届的统计表。核心是
**以固定模板为底（不必读取上一届表格），复用其所有 sheet 的表头/格式/结构，清空具体人员数据，
再从简历提取信息填入**。

本 skill 捕捉自“固定模板 → 2027届表格”流程，专为每年滚动复用、并可切换到不同岗位/城市设计。

## 前置：要知道什么

- **简历目录**：包含 N 份候选人简历 PDF（文件名含候选人姓名 + 岗位/城市，如 `C01427049-陈涛-_2027_硬件工程师-杭州.pdf`）。
- **固定模板文件**：`固定模板.xlsx`（含多个 sheet，主 sheet 默认「杭州岗」，表头行 2-3，列含
  姓名/性别/出生年份/联系方式/本科学校/本科专业/硕士学校/硕士专业/院校类别/意向城市等；面试安排 sheet
  表头 D2/E2 为「(待填写)」）。
- **岗位地点（可选，默认杭州）**：用于把第一个 sheet 重命名为「{地点}岗」、面试名单 sheet 重命名为
  「{地点}面试名单」。可询问用户；用户不明确时按默认杭州执行。
- **面试安排（可选，默认待定）**：用户给的时间（如 D=9.19（周五）/E=9.20（周六））填到面试安排表头
  D2/E2；用户暂时不确定则两格填「待定」。
- **目标**：生成 `<X+1>届校招人员信息统计表.xlsx`，结构同模板，主 sheet 填入这批候选人，其余 sheet 保留框架。

## 总体流程（5 步）

### 1. 提取简历文本
对所有 PDF 调用 `scripts/extract_pdfs.py`（基于 PyMuPDF，支持中文），输出 UTF-8 `.txt` 到备份目录。
> 依赖：需要 `pymupdf`。若 `import pymupdf` 失败，见文末「依赖安装」。

命令（示例，目录按实际调整）：
```
python scripts/extract_pdfs.py <简历目录> <输出目录>
```

### 2. 读取模板结构
用 `scripts/read_template.py` 读取模板 xlsx **所有 sheet** 的：sheet 名、表头行、列名、合并单元格、
数据起始行。这决定了后面填充哪些列、从第几行开始写。
```
python scripts/read_template.py <模板.xlsx>
```
输出到 `_template_dump.txt`（UTF-8）。重点记录主 sheet（如「杭州岗」）的每一列含义与列号对应关系。

### 3. 人工/模型解析简历 → 结构化数据 JSON
根据第 2 步的列映射，通读每份简历文本，提取下列字段（**主 sheet 个人信息列**）：
`姓名、性别、出生年份、联系方式(手机)、本科学校、本科专业、硕士学校、硕士专业、院校类别、意向城市`。

- **主 sheet 通常还含「笔试结果/面试时间/面试记录/面试得分/面试结果/面试批次/备注」等面试列，对新候选人一律留空**，待后续面试流程填写。
- 生成一个数据 JSON（UTF-8），结构见 `references/data_schema.md`。每份简历一条记录。
- 关键原则：**简历未明确标注的字段不要臆测**。性别、出生年份等若简历没写，值设为 `null`（留空），
  并在输出后向用户列出“需确认字段清单”，由用户补充；用「姓名显性给出/年龄推算」的出生年份需提示可能 ±1 年。
- 院校类别：用硕士学校判断 985 / 211 / 双一流 / 普通院校 / QS 排名。可参考模板自带「211&985院校名单」sheet；
  双一流的重点高校（如中国科学院大学、南京邮电大学等）按模板既有用法标注「双一流」。
- 意向城市 = 岗位城市（如「杭州」/「深圳」），一般全员一致。

### 4. 用固定模板生成新一届，并填充主 sheet
用 `scripts/build_next_year.py` 完成：
- **以固定模板为底**（不读取上一届）；
- **保留所有 sheet 的表头行、合并单元格、列宽、样式、结构**，清除原有具体人员数据；
- 在主 sheet 表头之后写入本批候选人（按数据 JSON）；
- **按地点重命名**：第一个 sheet →「{地点}岗」，`杭州` 前缀的 sheet →「{地点}面试名单」（如深圳）；
- **面试安排**：把用户时间（或「待定」）填到「面试安排」表头 D2/E2；其余 sheet 保留框架清空数据；
- 「211&985院校名单」等静态字典 sheet 原样保留。

```
python scripts/build_next_year.py <固定模板.xlsx> <输出.xlsx> <data.json> [config.json]
```
`config.json`（可选，字段都有默认值，参考 `CONFIG_DEFAULTS`）：
```json
{
  "location": "深圳",
  "interview_schedule": {"D": "9.19（周五）", "E": "9.20（周六）"}
}
```
不传 config 时默认 `location=杭州`、`interview_schedule={D:待定,E:待定}`。

### 5. 校验
用 `scripts/read_template.py` 读回生成的新一届文件，确认：主 sheet 表头完整（行 2-3）、N 名候选人顺序编号正确、
中文正常、电话/出生年份等为数值、面试列为空、sheet 名已按地点重命名、面试安排 D2/E2 时间（或待定）已填。
向用户报告每个 sheet 的处理结果与需确认字段。

## 后续有新增简历：增量追加（append）

表已生成后若又来新简历，**不必重建全表**，用 `scripts/append_candidates.py` 把新增简历**自动追加**进同一份表：

- 读取【已生成】的 Excel（如 `2027届校招人员信息统计表.xlsx`），解析主表已有候选人；
- 按「姓名」或「联系方式」去重：**已存在的自动跳过**，只追加真正新增的；
- 序号自动续号（从已有最大序号 +1 开始）；沿用主表数据行的样式/列结构，视觉一致；
- **只改主表**，其余 sheet（面试名单/面试安排/211&985院校名单/录用填写表）原样不动；
- **绝不覆盖原文件**：输出自动另存为一个新副本（`<原名>_新增.xlsx`，重名自动加序号），原文件保持不变。

```
python scripts/append_candidates.py <已生成.xlsx> <新增data.json>
```
`新增data.json` 结构与 build 用的 data.json 相同（`candidates` + `column_map`），只含新增的几份简历。
输出默认生成 `<已生成.xlsx 同名>_新增.xlsx`；若要指定输出名，加第三个参数：
`... <已生成.xlsx> <新增data.json> <输出.xlsx>`（即使传成原文件也会强制另存，绝不覆盖）。
脚本会在终端打印「已有 X 名、跳过谁、新增谁、新数据写到第几行」供确认。

## 输出
- 主交付物：`<X+1>届校招人员信息统计表.xlsx`（格式与原模板一致）。
- 可选附产物：同数据的 `.csv` / `.json`、简历抽取的 `.txt` 文本备份。

## 依赖安装（重要）
- 构建脚本（`read_template.py`、`build_next_year.py`）**仅用 Python 标准库（zipfile/xml）**，无需第三方库。
- 只有 `extract_pdfs.py` 需要 **PyMuPDF**。
  - 正常环境：`pip install pymupdf`（或 `python -m pip install pymupdf`）。
  - 若 pip 因系统 TEMP 被劫持（如 `C:\Users\Public\Documents\Wondershare\CreatorTemp` 报 Permission denied）导致安装失败，
    大概率是 **Python `tempfile` 优先读 `TMPDIR` 环境变量**指向了被占用的目录。解决：先把
    `TMPDIR`、`TMP`、`TEMP` 三个环境变量指向一个可写目录再装。
  - 若仍失败，可到 PyPI 下载 `pymupdf-<ver>-cp310-abi3-win_amd64.whl`，用 `zipfile` 解压到本地目录并把该目录加入
    `sys.path`（PyMuPDF 无第三方运行时依赖）。

## 工作目录约定
- 所有中间产物（抽取的 txt、数据 json、模板 dump）放到工作目录下的 `_extracted/`、`_skill_work/` 等子目录，避免污染简历原目录。
- 完成后清理临时文件（模板副本、依赖目录等），保留主交付物与必要脚本。
